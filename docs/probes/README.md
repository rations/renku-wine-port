# Probes

Small standalone programs that establish the facts
[OSMESA-GL-PLAN.md](../OSMESA-GL-PLAN.md) and [NATIVE-DRIVER-PLAN.md](../NATIVE-DRIVER-PLAN.md)
are built on. They are the reason the plan chose OSMesa
over EGL and over Vulkan/DXVK — rerun them before trusting any of those conclusions on a
different RenkuOS revision or Mesa version.

Build and run on the target machine:

| Probe | Build | Establishes |
|---|---|---|
| `osprobe.c` | `cc osprobe.c -o osprobe -lOSMesa` | **The plan's foundation.** OSMesa gives headless desktop GL with no window: `OSMesaCreateContextAttribs` + `OSMesaMakeCurrent` into a malloc'd RGBA8 buffer yields GL 4.5 compat / llvmpipe and renders a correct frame. Plan §1. |
| `eglprobe.c` | `cc eglprobe.c -o eglprobe -lEGL -lGL` | **The dead end that ruled out EGL.** Surfaceless/device EGL is advertised as a *client* extension but `eglInitialize` fails with `EGL_NOT_INITIALIZED`, and there is no Wayland EGL platform at all — so `winewayland.drv`'s existing EGL path can never work on RenkuOS. Plan §1. |
| `vkenum.c` | `cc vkenum.c -o vkenum -lvulkan` | Vulkan instance/device enumeration. |
| `vkext.c` | `cc vkext.c -o vkext -lvulkan` | **The dead end that ruled out DXVK.** The Vulkan loader exposes no surface extensions, so there is no WSI to present through. Plan §7. |
| `beprobe.cpp` | `g++ -O1 -Wall beprobe.cpp -o beprobe -lbe` | **The native driver's threading model** (NATIVE-DRIVER-PLAN.md §3, P1+P2): a BApplication run off the main thread, a window created, locked and invalidated from another thread, looper events waking that thread's `poll()` through a pipe. Prints PASS/FAIL per check; exit status = failures. Opens one small window for about a second. Passed 11/11 on the RenkuOS build VM, 2026-11-10. |
| `winprobe.cpp` | `g++ -O1 -Wall winprobe.cpp -o winprobe -lbe` | **Window behaviour the native driver relies on** (NATIVE-DRIVER-PLAN.md §3, P4): exact and off-screen placement, popups that never take focus, modal subsets, decorator insets and size limits. Passed 14/14 on the RenkuOS build VM, 2026-11-10. |
| `sigprobe.c`, `sigprobe_be.cpp`, `sigprobe.h` | Winelib, against a built Wine tree `$W`: `g++ -O1 -Wall -fPIC -c sigprobe_be.cpp` then `$W/tools/winegcc/winegcc --wine-objdir $W -mconsole -o sigprobe.exe sigprobe.c sigprobe_be.o -L$W/libs/winecrt0 -L$W/dlls/kernel32 -L$W/dlls/ntdll -lwinecrt0 -lkernel32 -lntdll -lbe -lstdc++`. With `--wine-objdir`, winegcc adds no default libraries, so they are listed. Run `$W/loader/wine sigprobe.exe.so [--unblocked|--fault]` | **Wine's signals and Be threads in one process** (NATIVE-DRIVER-PLAN.md §3, P3): thread masks on the loopers, thread- and process-directed SIGINT, a fault on a looper. Needs a prefix seeded with `sigprobe-user.reg` (`Graphics=null`), on a REVISION 2+ build (`--without-opengl`; on REVISION 1, libEGL must be shadowed, see §3). **Passed 15/15**, 2026-11-11; the `--unblocked` control faults on the looper and `--fault` freezes the looper silently (plan §3). |
| `kbdprobe.c` | Winelib, like sigprobe: `$W/tools/winegcc/winegcc --wine-objdir $W -mconsole -o kbdprobe.exe kbdprobe.c -L$W/libs/winecrt0 -L$W/dlls/kernel32 -L$W/dlls/ntdll -L$W/dlls/user32 -lwinecrt0 -lkernel32 -lntdll -luser32`. Run `$W/loader/wine kbdprobe.exe.so` in a prefix that uses `winerenku.drv` | **The keyboard layout tables** (patch 19): for a set of keys, the virtual key, the characters plain, with Shift and with AltGr, and the key name, then `VkKeyScan` for a few characters. Load a keymap with `keymap -l /boot/system/data/Keymaps/<name>` (back up `~/config/settings/Key_map` first) and compare with its source in `src/data/keymaps`. Matched US, US-International, German and French on the RenkuOS build VM, 2026-11-11. |
| `gltest.c` | winegcc, run under Wine | Gate 2 of the plan's test plan (§5): a Win32 app creating a GL context *through Wine*. Under the OSMesa backend it should print llvmpipe 4.5 with no `Failed to find a suitable pixel format`. Superseded by `glprobe.c`. |
| `glprobe.c` | `x86_64-w64-mingw32-gcc -O1 -Wall -o glprobe.exe glprobe.c -lopengl32 -lgdi32 -luser32`; run `wine glprobe.exe --screen \| ./screencheck` | **Gates 2 and 4** under `winerenku.drv` (patch 20): legacy and 3.2 core contexts through the driver with their GL strings; a test pattern (top green, bottom red) read back with `glReadPixels` and on the screen, so colour order and orientation are checked; a GL child window inside a top-level one, as a plug-in editor is; the same child overlapped by a sibling (drawn with GDI, checked with `GetPixel` too, the sibling stays on top); the last frame of a burst left on screen; a resize. Screen points are printed as `SCREEN x y rrggbb what` for `screencheck`. PASS/FAIL per check, exit status = failures. Passed 29/29 three times in the RenkuOS build VM, 2026-11-11 (llvmpipe, GL 4.5). |
| `d3dprobe.c` | `x86_64-w64-mingw32-gcc -O1 -Wall -o d3dprobe.exe d3dprobe.c -ld3d9 -ld3d11 -ldxgi -lgdi32 -luser32`; run `wine d3dprobe.exe --screen \| ./screencheck` | **Gate 3**: wined3d creates a D3D9 device and a D3D11 device with a swap chain on the driver's GL; each clears to a colour and presents, and the colour is checked on the screen. Passed 8/8 three times in the RenkuOS build VM, 2026-11-11 (D3D11 feature level 11_0). |
| `hostprobe.c`, `hostprobe_host.cpp` | Winelib, like kbdprobe, with gdi32 and opengl32 added: `$W/tools/winegcc/winegcc --wine-objdir $W -mconsole -o hostprobe.exe hostprobe.c -L$W/libs/winecrt0 -L$W/dlls/kernel32 -L$W/dlls/ntdll -L$W/dlls/user32 -L$W/dlls/gdi32 -L$W/dlls/opengl32 -lwinecrt0 -lkernel32 -lntdll -luser32 -lgdi32 -lopengl32`; the host: `g++ -O1 -Wall -I$W/dlls/winerenku.drv hostprobe_host.cpp -o hostprobe_host -lbe`; run `$W/loader/wine hostprobe.exe.so \| ./hostprobe_host \| ./screencheck` | **The driver's hosted mode** (patch 20): a Winelib window that asks for it, with a GL child and an owned popup, shown by a native program in a view of its own through the protocol in `renku_host.h`. Checks the pixels and their placement on screen, focus, a click, a key, a repaint, the GL child (GDI path), the wheel, moving the host window, the popup's position after the move, and the window going away. PASS/FAIL per check, exit status = failures. Passed 20/20 three times in the RenkuOS build VM, 2026-11-12. Stop the screensaver first, as for screencheck. |
| `screencheck.cpp` | `g++ -O1 -Wall screencheck.cpp -o screencheck -lbe` | Reads `SCREEN x y rrggbb what` lines from stdin (from glprobe and d3dprobe), reads that pixel from the screen with `BScreen::GetBitmap`, prints PASS/FAIL; other lines pass through; exit status = failures. Needed because a GL window's frames in a view of their own never pass through anything Win32 can read back. It reads what is really on screen, so the screen must be showing the desktop: with the screensaver running (`screen_blanker`, its window covers everything) every check reads `000000` and fails. |

Recorded on the test laptop, 2026-07-24, Mesa 22.0.5, system revision hrev59867.
